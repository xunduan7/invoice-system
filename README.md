# 材料费发票智能预审与管理平台

本项目由前端成员**魏韵童**与后端成员**吴梓涵**共同完成。平台支持 PDF/ZIP 发票上传、信息提取与人工核对、材料费规则预审、支付凭证核验，以及资质、财务和报销状态管理。管理员依据原件和系统提示作最终审核。

## 团队分工

| 分工 | 主要工作 |
| --- | --- |
| 魏韵童（前端） | 负责 Vue 页面布局与交互、登录和发票工作区、详情弹窗、字段与商品明细编辑、凭证上传界面、审核操作入口、状态展示，以及请求封装和接口联调。 |
| 吴梓涵（后端） | 负责 Spring Boot 接口、PDF/ZIP 文件处理、文本与 OCR 提取、AI 结构化接入、数据库表和数据访问、品类与金额规则、凭证核验和审核状态流转。 |
| 两人共同 | 对照考核需求确定操作流程，完成前后端联调、样本场景验证、演示材料和提交文档。 |

## 技术与目录

| 部分 | 技术 / 用途 |
| --- | --- |
| `frontend/` | 魏韵童负责。Vue 3、Vite、Axios；页面、交互和 API 请求。 |
| `backend/` | 吴梓涵负责。Java 17、Spring Boot、JDBC；接口、文件处理、规则引擎和数据访问。 |
| PDF 与 OCR | PDFBox 优先读取 PDF 文本层；文本不可用时尝试本机 Tesseract（中文和英文语言数据在 `backend/tessdata/`）。 |
| AI | 阿里云百炼兼容接口，用于发票字段结构化及未命中长期规则的商品语义分类。 |
| 数据 | 默认使用本地 H2；可选 MySQL profile。原始文件存后端磁盘，数据库保存记录和文件路径。 |
| `sample-data/` | 虚构的 PDF、ZIP、订单截图和支付记录，用于演示和规则测试。 |

魏韵童在 `frontend/src/api.js` 集中封装接口和 Token 处理，通过 Vite 将 `/api` 代理到本机后端 `8080` 端口；吴梓涵在后端提供对应的业务接口。接口清单见 [`backend/docs/API.md`](backend/docs/API.md)，页面与接口的对应关系见 [`接口对照.md`](接口对照.md)。

## 运行环境与启动

- Windows 演示环境；Java 17、Maven、Node.js（`20.19+` 或 `22.12+`）和 npm。
- OCR 扫描件需要单独安装 Tesseract 可执行程序。`backend/tessdata/` 提供语言数据，但不能代替 Tesseract 程序本身。
- 在线 AI 通过百炼 API Key 和网络连接运行；人工核对与程序规则流程也可以独立使用。

在**解压后的项目根目录**依次运行：

1. 双击 `启动后端.cmd`，等待后端启动；它在 `http://127.0.0.1:8080` 提供接口。首次运行 Maven 可能下载依赖。
2. 双击 `启动前端.cmd`，首次运行会执行 `npm ci`；在浏览器打开 `http://127.0.0.1:5173/`。
3. 首次使用点击“创建账号”，之后用该账号登录。登录、上传和审核接口使用 Token。

也可在两个终端分别执行 `cd backend && mvn spring-boot:run`、`cd frontend && npm ci && npm run dev`。项目由魏韵童负责的前端页面与吴梓涵负责的后端服务共同运行。

### AI Key 与 OCR 配置

将根目录的 `local-ai-key.example.cmd` **复制**为 `local-ai-key.cmd`，用文本编辑器将 `YOUR_KEY_HERE` 改为自己的 Key，然后重新运行 `启动后端.cmd`。启动脚本会读取该本地文件；也可以直接设置环境变量 `DASHSCOPE_API_KEY`。默认模型和接口地址配置在 `backend/src/main/resources/application.properties`，可通过 `DASHSCOPE_MODEL`、`DASHSCOPE_ENDPOINT` 调整。真实 Key 不写入源码、README 或演示视频；`local-ai-key.cmd` 已被 Git 忽略。

启动脚本会尝试识别 `C:\Program Files\Tesseract-OCR\tesseract.exe`。安装在其他位置时，设置 `TESSERACT_EXE` 环境变量。吴梓涵在后端实现文本提取、OCR 调用和 AI 结构化；魏韵童在发票详情中展示识别结果与人工核对入口。

### 数据库

吴梓涵设计并维护后端数据访问。默认 `demo` profile 使用 H2 文件库 `backend/data/invoice_review.mv.db`，初始化 SQL 位于 `backend/src/main/resources/schema-h2.sql`。也可启用 `mysql` profile，并配置 `DB_URL`、`DB_USER`、`DB_PASSWORD`。本机数据库、上传文件、依赖和构建目录均由 `.gitignore` 排除；克隆仓库后首次使用需创建账号。

## 功能与操作流程

### 1. 上传、列表与原件预览

魏韵童实现登录后的总览、发票管理列表、搜索筛选、上传操作和详情弹窗，并将上传结果、处理状态与重复提示展示在页面上。吴梓涵实现 PDF/ZIP 上传接口：保存原始文件，递归查找 ZIP 子目录中的 PDF，每张 PDF 独立建档，并提供发票原件预览接口。

### 2. 信息提取与人工核对

吴梓涵使用 PDFBox 读取文本层，必要时调用 Tesseract OCR，再通过百炼将文本结构化为发票字段和商品明细；原始文本与 AI 原始结果一并保存。魏韵童在详情页展示提取结果、原件与核对提示，提供字段修正、商品明细补全和品类人工调整的交互。后端保存修改记录，便于回看人工处理过程。

### 3. 品类判断与自动预审

吴梓涵实现长期品类关键词规则和“可以 / 存疑 / 不可以”结论；未命中长期规则的商品可由 AI 辅助判断。程序校验必填字段、金额关系、重复发票、单价以及同商家自然周累计：单价达到 1000 元按资产拦截；单价达到 500 元的低值品要求凭证；周累计超过 1000 元要求相关凭证，超过 3000 元拒绝当前发票。魏韵童在品类规则页、发票详情和待办审核页展示结论、原因和后续操作入口。人工品类结论优先于自动分类。

### 4. 支付凭证与状态流转

魏韵童实现订单截图和支付记录上传界面、凭证预览、核验按钮、资质审核、财务提交与最终报销的操作界面，并在列表和历史页区分三个状态。吴梓涵实现凭证文件保存、凭证组数据关系、人工核验接口及状态流转校验：资质通过后进入财务流程，财务审核通过后记录最终报销。符合条件的发票可填写原因后取消。

## 文件与数据库设计

吴梓涵负责数据库表与关系设计：`invoice` 保存发票字段、上传时间、文件路径、提取文本、AI 原始 JSON、预审状态以及资质、财务、报销状态；`invoice_item` 保存商品明细；`payment_evidence` 是凭证组，`order_screenshot` 与 `payment_record` 分别保存两类凭证的文件记录；`category_rule` 和 `category_override` 保存长期规则及人工品类结论；`invoice_edit_log` 保存修改记录；`sys_user`、`sys_token` 支持登录。魏韵童依据这些数据关系组织发票详情、凭证和历史记录页面。

PDF、原始 ZIP、ZIP 解压后的 PDF 和凭证文件保存在 `backend/uploads/`。数据库记录文件路径，前端通过带 Token 的接口请求原件和凭证预览。
